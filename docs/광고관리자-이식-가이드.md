# 광고관리자 메뉴 이식 가이드

> 이 문서는 danarobe/dnrb-dashboard(공개 레포)의 **광고관리자(#admgr) 메뉴를 다른 프로젝트로 옮겨 이어서 개발**하려는 사람(과 그 사람의 Claude)을 위한 지침서다.
> 원본 소스: https://github.com/danarobe/dnrb-dashboard — 전부 열람 가능하니 레포를 클론해서 아래 위치의 코드를 가져가면 된다.
> 문서 기준일: 2026-09-01 (이후 커밋으로 줄 번호가 밀릴 수 있으니 **줄 번호보다 함수명·주석 마커로 찾을 것**).

---

## 0. 이게 뭔가 (아키텍처 한 장)

- **화면**: 프레임워크 없는 순수 HTML/JS 단일 페이지(`index.html`) 안의 한 메뉴. 표는 innerHTML 통짜 생성.
- **서버**: Supabase Edge Function(Deno/TypeScript) 2개 — `meta-ads`(읽기 전용), `meta-budget`(예산 쓰기 전용, 선택).
- **외부 API**: Meta Marketing API (Graph **v23.0**), 시스템 사용자 무기한 토큰.
- **DB**: Supabase Postgres 테이블 5개(아래 §4) — 판정·메모·베스트 목록·스냅샷·캐시 저장용.
- 핵심 설계: **Meta 호출은 전부 서버에서, 결과는 서버 캐시(60초~10분)** — 클라이언트가 Meta를 직접 부르지 않는다. 이 캐시가 Meta 호출 한도(rate limit) 방어선이다(실사고 있었음, §7-1).

기능 요약: 캠페인/광고세트/광고 3계층 탭(체크 선택 연동), 테스트 소재 탭(자동 수집+우수/애매/OFF 판정+추가소재 체크+테스트 종료 보관), 기존광고 중 OFF 탭(기간 내 꺼진 세트), 베스트소재 탭(소재 격자 보드), 소재 미리보기 모달, 예산 직접 변경+자정 예약(선택), 엑셀 추출, 열 너비 조절, 다중 정렬.

## 1. 가져갈 코드 위치 (index.html)

| 구성 요소 | 위치 찾는 법 |
|---|---|
| 섹션 마크업 | `id="sec-admgr"` div 통째 (탭·검색·기간 칩·요약 타일·결과 영역·컨트롤 스팬들) |
| 소재 미리보기 모달 | `id="meta-preview-modal"` div (광고 효율 메뉴와 공유하는 부품) |
| 광고관리자 JS 블록 | 주석 `광고관리자 (#admgr` 로 시작하는 블록 — `const admgrState = {` 부터 다음 `/* ══════` 구분 주석 전까지 전부 (약 1,600줄, `admgr*` 접두 함수 ~100개) |
| 미리보기 함수 | `async function showMetaPreview(` + `metaStatsChart` 전역 (광고 효율 블록에 있음 — 함께 복사) |
| 메뉴 버튼·진입 훅 | `menu-admgr` 버튼, `MENU_KEYS` 배열의 `'admgr'`, `showMenu`의 admgr 분기 — 이식처의 라우팅 방식에 맞게 재작성 |

### 반드시 함께 가져가야 하는 공용 헬퍼 (admgr가 의존)

- `$` (getElementById 축약), `fmt`(천단위 콤마), `escHtml`, `showToast`
- `btnBusy`/`btnIdle` + `__btnTimers` Map — ⚠ btnBusy 첫 줄의 `clearInterval(__btnTimers.get(btn))`을 빼먹으면 여러 조회가 한 버튼을 공유할 때 '불러오는 중 N초'가 무한 카운팅되는 버그가 재발한다(실사고).
- `uiTabs(containerId, defs, activeKey, onclick)` — 밑줄형 탭 공용 부품
- `dbProxy(path, init)` — DB 접근 (이식처의 백엔드에 맞게 교체 지점, §5)
- `metaGet(params)` + `fnUrl`/`sbHeaders` — meta-ads 함수 호출 래퍼
- `admgrColResize` 계열은 admgr 블록 안에 포함되어 있음
- XLSX 추출을 쓰려면 CDN `xlsx-populate` + `admgrTestXlsx` (블록에 포함)

### CSS 의존

- `.table-wrap`(가로 스크롤 표), `.m-hide`(모바일 열 숨김, ≤700px), `.empty-state`, 버튼류(`.btn-analyze`, `.toggle-btn`), 글래스 카드 스타일. 이식처 스타일로 대체해도 되지만 `.m-hide`와 `.table-wrap` 개념은 유지 권장(모바일 넘침 방지).
- ⚠ **미리보기 모달은 body 직속에 둘 것** — 조상에 `backdrop-filter`가 있으면 `position:fixed` 기준이 깨져 모달이 엉뚱한 곳에 뜬다(실사고).

## 2. 가져갈 서버 파일

| 파일 | 역할 |
|---|---|
| `supabase/functions/meta-ads/index.ts` | 읽기 전액션: `hierarchy`(계층 4호출 조립)·`testads`(테스트 소재+스냅샷)·`offsets`(기간 내 OFF 세트)·`creatives`(베스트소재 썸네일)·`budgethistory`(예산 변경 이력)·`hourlystats`(시간대 성과)·`adstats`(기간 7종 성과)·`preview`(미리보기 iframe). `summary/topads/dateads/activeads/syncexport`는 이 대시보드 전용이라 **빼도 됨** |
| `supabase/functions/meta-budget/index.ts` | 예산 즉시 변경·자정 예약(pg_cron). **위험 기능 — 2단계로 미루기 권장** (§8) |
| `supabase/functions/_shared/util.ts` | CORS·인증·캐시(`cacheGet/cacheSet` → api_cache 테이블)·json 헬퍼 |

Supabase를 안 쓰는 프로젝트라면: meta-ads/index.ts는 fetch 기반 순수 로직이라 Node/기타 서버로 옮기기 쉽다. 반드시 유지할 것 두 가지 — **① 토큰을 서버에만 두기 ② 결과 캐시(hierarchy·testads 60초, creatives 10분)**.

## 3. Meta 쪽 준비 (이식받는 사람이 직접 해야 함)

1. Meta 비즈니스 설정 → **시스템 사용자** 생성 → 광고계정 자산 할당 → **ads_read 권한 무기한 토큰** 발급. (개인 계정 토큰은 잠금·만료 문제로 비권장 — 우리도 시스템 사용자로 갈아탄 이력 있음)
2. 확보할 값: `META_ACCESS_TOKEN`(읽기), `META_AD_ACCOUNT_ID`(숫자만, act_ 제외).
3. 예산 변경까지 쓰려면: **별도의 쓰기 토큰**(캠페인 관리 권한 + ads_management)을 만들어 `META_WRITE_TOKEN`으로 분리 보관 — 읽기 함수에는 절대 싣지 않는다(우리 보안 원칙).

## 4. DB 스키마 (그대로 실행)

```sql
-- 테스트 소재 판정·메모·추가소재 체크 (광고 단위)
create table if not exists ad_test_state (
  ad_id text primary key, ad_name text not null default '',
  hidden boolean not null default false, recommend boolean not null default false,  -- recommend는 폐기됐지만 코드 호환용
  memo text, verdict text check (verdict is null or verdict in ('meh','good')),
  asset_req_at timestamptz, asset_done_at timestamptz,
  updated_by text, updated_at timestamptz default now());

-- 베스트소재 보드 (광고세트 단위)
create table if not exists best_ads (
  adset_id text primary key, adset_name text not null default '',
  added_by text, created_at timestamptz default now());

-- 테스트 소재 스냅샷 — 세트명에서 test를 지워도 '테스트 종료'로 계속 보이게
create table if not exists test_ad_snap (
  ad_id text primary key, name text not null default '', adset_id text not null default '',
  adset_name text not null default '', status text not null default '', effective_status text not null default '',
  reg_date text not null default '', spend numeric not null default 0, purchases numeric not null default 0,
  value numeric not null default 0, first_seen timestamptz default now(), last_seen timestamptz default now());

-- 서버 결과 캐시 (rate limit 방어선 — 필수)
create table if not exists api_cache (
  cache_key text primary key, payload jsonb, created_at timestamptz default now());

-- 예산 변경 기록 (meta-budget 쓸 때만)
create table if not exists budget_writes (
  id uuid primary key default gen_random_uuid(), kind text, object_id text, object_name text,
  old_value numeric, new_value numeric, status text, requested_by text, run_at timestamptz,
  created_at timestamptz default now());

-- 전 테이블 RLS 켜고 정책 없이 두기 — 접근은 서버(service_role)와 인증 프록시로만
```

## 5. 이식처에 맞게 갈아끼울 지점 (어댑터 2곳)

1. **인증**: 우리는 자체 로그인(`verifyAuthToken`, 역할 admin/staff)을 쓴다. meta-ads 상단의 인증 검사와 클라이언트의 `isAdmin()/isStaff()` 분기(테스트 소재 탭만 MD 허용 등)를 이식처의 인증으로 교체. 역할 구분이 없다면 전부 허용으로 단순화해도 된다 — 단 **토큰이 서버 밖으로 안 나가는 구조는 유지**.
2. **DB 접근**: 클라이언트 `dbProxy()`는 우리 db 프록시 함수를 부른다. 이식처에서는 자기 백엔드 CRUD로 교체 — admgr가 쓰는 테이블은 §4의 5개뿐이고 호출 지점은 `dbProxy(` 검색으로 전부 나온다 (ad_test_state upsert/select, best_ads CRUD).

## 6. 운영 규칙 (코드가 전제하는 사내 약속 — 안 지키면 기능이 빈다)

- **테스트 소재 자동 수집**: 광고세트명에 `test`(대소문자 무시)를 넣으면 자동으로 테스트 소재 탭에 잡힌다. 서버 `kw` 파라미터로 키워드 변경 가능.
- **광고명에 등록일 YYMMDD** 기입(예: 260810) — dateads 기능용(우리 전용이라 빼도 됨).
- 테스트 종료 = 세트명에서 test 제거. 스냅샷 덕에 화면에는 '테스트 종료' 배지로 60일간 남는다.

## 7. 실측으로 얻은 함정 목록 (⚠ 새로 개발하다 밟기 쉬운 것들)

1. **Meta 호출 한도**: 반복 조회로 "User request limit reached" 실사고 — 서버 캐시(60초)가 방어선. 캐시 없이 돌리지 말 것.
2. **500개 한도 잘림**: /ads·/adsets 무필터 조회는 500개에서 잘려 캠페인이 통째로 누락된다 → **하향식 조립**(/campaigns + /adsets + /ads 활성 필터 + insights level=ad 4호출) + 페이지네이션(`graphGetAll`)이 정답.
3. **Meta id는 17자리** — `Number()` 비교는 2^53 초과로 정밀도가 깨진다. 문자열(자릿수→사전순) 비교 함수 `admgrIdCmp` 사용.
4. **활동 로그(activities)의 object_type은 옛 명칭** — CAMPAIGN이 광고세트를 뜻함! 층 판정은 event_type으로. event_time은 UTC(+9h 표시). 보관 약 90일.
5. **`?ids=` 배치 조회는 "deprecated in v26.0+" 오류** — 개별 조회 또는 목록+필터로.
6. **영상 원본(mp4) 접근**: `/{video_id}?fields=source`는 ads_read·ads_management 모두 #10 권한 거부. 계정 라이브러리(`act_X/advideos`) 목록에는 source가 열리지만, 인스타 게시물 기반 광고는 라이브러리에 없다. → 소재 보기는 **미리보기 iframe**(preview 액션)으로 통일했다. 호버 자동재생은 페이지 자산 권한 없인 불가.
7. **미리보기 형식**: `INSTAGRAM_STANDARD`가 안정적. REELS 형식은 모달에서 잘리고 재생이 안 되는 실사례.
8. **effective_status는 상위 상태가 전파**된다(캠페인 꺼짐 → 세트 CAMPAIGN_PAUSED). '활성만' 판정과 OFF 감지에서 이 점 고려.
9. **date_preset은 광고계정 시간대 기준** — last_7d 등은 오늘 제외 어제까지. '이전 7일'은 프리셋이 없어 time_range로 직접.
10. **innerHTML 재렌더 시 표 스크롤 유지** — 렌더 끝에서 `.table-wrap`의 scrollTop/Left를 보관·복원해야 클릭마다 맨 위로 튀지 않는다 (코드에 포함돼 있으니 지우지 말 것).

## 8. 이식 순서 제안 (단계별)

1. **1단계 — 읽기 전용 계층 뷰**: meta-ads의 `hierarchy` + 클라 캠페인/세트/광고 3탭 + 미리보기 모달. (secrets 2개 + api_cache만 있으면 동작)
2. **2단계 — 테스트 소재**: `testads` 액션 + ad_test_state/test_ad_snap 테이블 + 판정·추가소재·테스트 종료.
3. **3단계 — 부가 탭**: `offsets`(기존광고 중 OFF), `creatives`+best_ads(베스트소재), 엑셀 추출.
4. **4단계(선택, 신중히) — 예산 쓰기**: meta-budget + 쓰기 토큰 + PIN·허용자·상한 같은 안전장치. 실돈이 움직이는 기능이라 우리는 서버 강제 5중 안전장치(admin+허용 id 목록+PIN+일예산 상한+전 기록)를 달았다 — 그대로 가져가길 강력 권장.

## 9. 우리 대시보드 전용이라 빼고 시작할 것

- 광고세트 탭 '실결제 수' 열 (카페24 paiditems 의존) — `admgrPaidCell`/`paid` 관련
- `syncexport` 액션 (우리 상품관리 시스템 연동)
- `activeads`/`dateads`/`summary`/`topads` (판매 성과·광고 효율 메뉴용)
- 역할별 금액 블러(`admgrMoney` vs `admgrMoneyPlain`) — 이식처에 역할 구분 없으면 Plain으로 통일
